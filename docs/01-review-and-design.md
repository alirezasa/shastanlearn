# پایگاه دانش شستان — بررسی قالب و طراحی سامانه روی SharePoint Server 2019

> این سند شامل بررسی نهایی قالب اولیه (`_original/`)، معماری، نقش‌ها و مجوزها، ساختار لیست‌ها و
> امکانات صفحات است. راهنمای گام‌به‌گام نصب در [`02-deployment.md`](02-deployment.md) آمده است.

## ۱. بررسی قالب اولیه (`_original/index.html`، `post.html`، `asset/`)

| # | مورد | اثر | اصلاح در نسخه‌ی جدید |

| 9 | پنل اعلان و اسلایدر ثابت‌اند؛ اسلایدر روی موبایل Swipe و روی کیبورد دسترس‌پذیری ندارد | | اسلایدر محتوای ویژه با Swipe، توقف هنگام هاور، دکمه‌های قابل دسترسی |

> تنظیمات خاص لیست `KnowledgeContent`)، آن را بفرستید تا با این بسته هماهنگ شود.

## ۲. معماری

```
http://srv-shp-web  (Zone: Default — Windows Auth + Anonymous)
 ├─ KBPages/            index.aspx · browse.aspx · content.aspx       ← عمومی (ناشناس: فقط مشاهده)
 ├─ KBPanel/            panel.aspx                                     ← فقط کاربران واردشده
 ├─ KBAssets/           css · js · fonts · img                         ← عمومی
 ├─ DocLib/             کتابخانه‌ی رسانه‌ی عمومی (تصویر، ویدیو، صوت، سند)  ← عمومی
 ├─ Lists/KnowledgeContent   محتوا + پیوست‌ها                          ← فقط KB-HR و KB-Admins
 ├─ Lists/KBCategories · KBComments · KBReactions · KBSettings · KBAuditLog
 ├─ _catalogs/masterpage/kb.master
 └─ _layouts/15/KB/KBApi.ashx     سرویس سمت سرور (C#، بدون WSP)
```

### چرا سرویس سمت سرور (KBApi.ashx)؟
شیرپوینت **امنیت ستونی** ندارد و دسترسی ناشناس را فقط در سطح لیست/کتابخانه می‌توان تعیین کرد. اگر لیست محتوا
برای ناشناس باز شود، محتوای «خصوصی» و پیش‌نویس‌ها هم با یک درخواست REST قابل خواندن است. بنابراین:

1. لیست `KnowledgeContent` **هیچ** دسترسی‌ای برای ناشناس و کاربران عادی ندارد (فقط KB-HR و KB-Admins).
2. `KBApi.ashx` با دسترسی سیستمی می‌خواند و **فقط** محتوای «منتشرشده» را برمی‌گرداند:
   «عمومی» برای همه، «خصوصی» فقط برای کاربر واردشده.
3. پیوست‌ها هم از همین سرویس و با همین قاعده دریافت می‌شوند (با پشتیبانی از Range برای پخش و جلو/عقب بردن ویدیو).
4. پسند، ذخیره، نظر و بازدید با **هویت واقعی کاربر** (نه مقدار ارسالی مرورگر) ثبت می‌شوند.
5. عملیات مدیریتی (ذخیره، انتشار، حذف) با **مجوز خود کاربر** انجام می‌شود؛ شیرپوینت مجوز را اعمال می‌کند و
   ستون‌های «ایجادکننده / ویرایشگر» و تاریخچه‌ی نسخه‌ها درست ثبت می‌شوند.

مزیت جانبی: چون ناشناس از REST استفاده نمی‌کند، **Lockdown Mode روشن می‌ماند** و کاربر ناشناس به فرم‌ها و
نمای لیست‌ها (`AllItems.aspx`، `DispForm.aspx`) دسترسی ندارد.

### چرا صفحات کلاسیک و مستر پیج جدا؟
تجربه‌ی Modern در SharePoint 2019 مستر پیج سفارشی و دسترسی ناشناس را پشتیبانی نمی‌کند. صفحات پایگاه دانش
در کتابخانه‌های جدا (`KBPages`، `KBPanel`) با مستر پیج `kb.master` هستند؛ **مستر پیج و صفحات فعلی سایت تغییر
نمی‌کنند** و `SitePages`/`SiteAssets` موجود عمومی نمی‌شوند.

### بدون مرحله‌ی Build
کدها JavaScript ساده (بدون وابستگی) و CSS دست‌نویس هستند؛ پوشه‌ی `sharepoint/` همان بسته‌ی نهایی است و
برای استقرار Node.js لازم نیست. اسکریپت استقرار، مسیر سایت و نسخه را در صفحات جایگذاری می‌کند.

## ۳. نقش‌ها و مجوزها

| گروه شیرپوینت | اعضا (از AD) | مجوز |
|---------------|--------------|------|
| (ناشناس) | همه | مشاهده‌ی `KBPages`، `KBAssets`، `DocLib` + داده از سرویس (فقط محتوای عمومی منتشرشده) |
| `KB-Readers` | همه‌ی کاربران واردشده (`c:0(.s|true`) | Read روی سایت؛ محتوای عمومی و **خصوصی** از سرویس؛ پسند، ذخیره، نظر |
| `KB-HR` | گروه AD منابع انسانی (مثلاً `KB-HR`) | «KB Editor» (ایجاد/ویرایش/حذف) روی محتوا، رسانه، دسته‌ها و نظرات + پنل مدیریت |
| `KB-Admins` | گروه AD مدیران سامانه | Full Control سایت + تنظیمات سامانه + گزارش فعالیت + تنظیمات شیرپوینت |

| مشاهده‌ی محتوای عمومی منتشرشده | ✅ | ✅ | ✅ | ✅ |
| مشاهده‌ی محتوای خصوصی | ❌ (صفحه‌ی ورود) | ✅ | ✅ | ✅ |

| حذف نظر | ❌ | فقط نظر خودش | ✅ | ✅ |

> اعمال می‌شوند و رابط کاربری فقط از آن پیروی می‌کند.

## ۴. لیست‌ها و ستون‌ها

### `KnowledgeContent` (لیست موجود شما)
ستون‌های موجود **حفظ می‌شوند**؛ اسکریپت نصب هر ستون را با نام داخلی یا عنوانش پیدا می‌کند و نگاشت را در
`KBSettings → FieldMap` ذخیره می‌کند. ستون‌های جاافتاده اضافه می‌شوند:

| ستون | نوع | توضیح |
|------|-----|-------|
| عنوان، Summary، Body | موجود | متن HTML (از ویرایشگر پنل) یا متن ساده |
| ThumbnailUrl، AuthorImageUrl | موجود | نشانی تصویر (Hyperlink یا متن؛ هر دو پشتیبانی می‌شود) |
| ContentType | موجود | نوع محتوا: مقاله، ویدیو، پادکست، راهنما، گزارش، گزارش تصویری، سند، خبر، اینفوگرافیک، پرسش و پاسخ (فارسی یا انگلیسی) |
| Category | موجود | متن، Choice یا Lookup |
| Views، ReadingMinutes، IsFeatured، AuthorName، AuthorBio، PublishAt | موجود | `PublishAt` در آینده = انتشار زمان‌بندی‌شده |
| **`KBVisibility`** | Choice: `Public` / `Private` | عمومی یا فقط کارکنان (پیش‌فرض ستون: Private) |
| **`KBStatus`** | Choice: `Draft` / `Published` / `Archived` | چرخه‌ی انتشار (ایندکس‌شده) |
| **`KBTags`** | متن | برچسب‌ها، جداشده با ویرگول |
| **`KBMediaUrl`** | متن | ویدیو یا صوت اصلی که بالای صفحه پخش می‌شود |
| **`KBLikes`، `KBCommentsCount`** | عدد | شمارنده‌ها (توسط سرویس به‌روز می‌شوند) |
| **`KBAllowComments`** | بله/خیر | فعال بودن نظرات |
| پیوست‌ها (Attachments) | — | فایل‌های اختصاصی هر محتوا؛ دسترسی تابع همان محتوا |

> ستون `ContentType` با ستون سیستمی «Content Type» شیرپوینت هم‌نام است؛ نام داخلی ستون شما احتمالاً
> `ContentType0` است و اسکریپت آن را درست تشخیص می‌دهد (خروجی «نگاشت ستون‌ها» را ببینید).

### لیست‌های جدید

| لیست | ستون‌ها | دسترسی مستقیم |
|------|---------|---------------|
| `KBCategories` | Title، Icon، Color، Description، SortOrder، IsActive | KB-HR ویرایش |
| `KBComments` | ContentId، ParentId، Body، AuthorName، AuthorLogin، Status (Approved/Pending/Hidden)، IsStaff، SourceIp | KB-HR ویرایش |
| `KBReactions` | ContentId، UserKey، Kind (Like/Bookmark) | KB-HR خواندن |
| `KBSettings` | Title (کلید)، Value | KB-HR خواندن |
| `KBAuditLog` | Action، ContentId، Actor، Details | KB-HR خواندن |

### کتابخانه‌ی رسانه `DocLib`
برای **رسانه‌ی عمومی** (تصویر شاخص، تصاویر و ویدیوهای داخل متن، عکس نویسنده). همه‌ی فایل‌های آن بدون ورود
قابل دریافت‌اند. فایل‌های محرمانه به‌صورت **پیوست همان محتوای خصوصی** بارگذاری می‌شوند. اگر محتوای «ویژه‌ی
کارکنان» از فایل‌های `DocLib` استفاده کند، پنل هنگام ذخیره هشدار می‌دهد و با یک کلیک آن‌ها را به پیوست منتقل می‌کند.

## ۵. صفحات عمومی

**صفحه‌ی اصلی** — Hero با جستجوی بزرگ و پیشنهاد فوری، برچسب‌های پرتکرار، آمار (محتوا، دسته، بازدید، ویدیو)؛
اسلایدر محتوای ویژه + سه کارت کناری؛ تازه‌ترین‌ها با تب نوع محتوا؛ دسته‌بندی‌ها با آیکن و تعداد؛ ویدیوهای آموزشی؛
دعوت به ورود برای محتوای ویژه‌ی کارکنان (فقط برای ناشناس، با تعداد)؛ پربازدیدترین‌ها و محبوب‌ترین‌ها.

**مرور و جستجو** (`browse.aspx`) — فیلتر نوع، دسته، برچسب، نویسنده، سطح دسترسی و «ذخیره‌شده‌های من»؛
مرتب‌سازی (مرتبط‌ترین، جدیدترین، پربازدیدترین، محبوب‌ترین، پربحث‌ترین، قدیمی‌ترین، عنوان)؛ نمای شبکه‌ای/فهرستی؛
صفحه‌بندی؛ همه‌ی فیلترها در نشانی صفحه ذخیره می‌شوند (قابل اشتراک).

**نمایش محتوا** (`content.aspx?id=12`) — مسیر راهنما؛ نوع، دسته و نشان «ویژه‌ی کارکنان»؛ نویسنده، تاریخ شمسی،
زمان مطالعه و بازدید؛ پخش‌کننده‌ی ویدیو/صوت یا تصویر شاخص؛ متن با فهرست مطالب خودکار، نوار پیشرفت مطالعه،
جدول، نقل‌قول، کد، گالری تصاویر (لایت‌باکس) و ویدیو/صوت داخل متن؛ برچسب‌ها؛ فایل‌های پیوست؛ پسند، ذخیره برای بعد،
اشتراک‌گذاری، چاپ/PDF و تغییر اندازه‌ی متن؛ معرفی نویسنده؛ نظرات با پاسخ و نشان «تیم محتوا»؛ مطالب مرتبط؛
برای محتوای خصوصی و کاربر ناشناس: صفحه‌ی «ورود کارکنان».

## ۷. ملاحظات

- **مرورگر:** Chrome، Edge و Firefox جدید. Internet Explorer پشتیبانی نمی‌شود.
- **حجم:** جستجو و فهرست‌ها روی حداکثر چند هزار محتوا سریع است (فهرست محتوای منتشرشده ۶۰ ثانیه در حافظه‌ی سرور نگه‌داری می‌شود).
- **حجم فایل:** سقف بارگذاری همان «Maximum upload size» وب‌اپلیکیشن است (پیش‌فرض ۲۵۰ مگابایت؛ برای ویدیوهای بزرگ در Central Admin افزایش دهید).
- ⚠️ **پشتیبانی SharePoint Server 2019** در ۱۴ ژوئیه‌ی ۲۰۲۶ به پایان رسیده است؛ آخرین CU نصب باشد و در صورت انتشار
  روی اینترنت، مهاجرت به Subscription Edition برنامه‌ریزی شود. این بسته بدون تغییر روی Subscription Edition هم کار می‌کند.
